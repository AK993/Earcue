# S4 · 本地流式 ASR 验证（sherpa-onnx）

## 目标

验证 M2 的核心假设：**16 kHz 环回音频 → 本地流式 Zipformer → 实时中文文本 + 端点断句** 能在 CPU 上稳定跑通，且延迟余量足够。

## 环境与模型

| 项 | 值 |
|---|---|
| 运行时 | .NET 8 / Windows 11 x64 |
| NuGet | `org.k2fsa.sherpa.onnx` 2.0.1 + `runtime.win-x64` |
| 模型 | `sherpa-onnx-streaming-zipformer-zh-14M-2023-02-23` |
| 量化 | int8 与 float 各测一轮 |
| 线程 | 2 |
| 解码 | `greedy_search` |
| 端点 | rule1 1.5s / rule2 0.6s / rule3 10s |
| 方式 | `tools/Spikes/ASR_Probe` 逐 10 ms 帧喂 WAV |

模型来自官方 release（sha256 `2CBD71B6…CBA8B`，70.6 MB 压缩包；int8 三件套约 25 MB）。安装脚本：`tools/download-asr-models.ps1`。

## 离线结果

| WAV | 量化 | 加载 | 解码（含 0.8s 尾部静音） | RTF | 最终文本 |
|---|---|---|---|---|---|
| `test_wavs/0.wav` (5.61s) | int8 | 1065 ms | 150 ms | 0.023 | 对我做了件事 / 我想说的是呢大家如果对我的研究感兴趣呢 |
| `test_wavs/0.wav` | float | 979 ms | 193 ms | 0.030 | 对我做了件事 / 我想说的是呢大家如果对我的研究感兴趣 |
| `test_wavs/1.wav` (5.15s) | int8 | 750 ms | 140 ms | 0.024 | 重点想谈三个问题 / 就是这一轮全球金融动量的表现 |
| `test_wavs/1.wav` | float | 1017 ms | 162 ms | 0.027 | 重点来想谈三个问题 / 首先呢就是这一轮全球金融动能的表现 |

参考文本（官方文档中的 Paraformer 结果）为“对我做了介绍啊那么我想说的是呢…”与“重点呢想谈三个问题首先呢就是这一轮全球金融动荡的表现”。

## 结论

1. **实时性余量很大**：RTF 0.023–0.030，10 ms 帧的处理成本约 0.2–0.3 ms，采集线程不会被识别拖慢。
2. **端点可用**：0.6s 静音后稳定切句，测试音频在 2.0s / 5.6s 处产生 final，符合会议“说完一句就出句”的节奏。
3. **int8 与 float 差距不大**：字面结果互有胜负，但 int8 加载更快、内存更小，作为默认更合适；`asr.useInt8=false` 可切浮点。
4. **14M 模型的准确率是取舍点**：中文可读，但专名/近音字会错（“介绍”→“件事”、“动荡”→“动量/动能”）。英文多的会议建议用双语模型（约 487 MB）；后续可加热词表。
5. **加载成本一次性 1s 左右**：已放在后台线程，点击启动时显示“正在加载 ASR 模型…”。

## 环回实测

在应用内点击 **启动采集与本地识别**：

- 模型加载 798–925 ms，状态栏显示 `ASR: 中文流式 Zipformer 14M · int8 · 925ms`；
- WASAPI 初始化 48 kHz / 2ch / float，自动转 16 kHz mono；
- 播放系统音频时，实时草稿行滚动，约 0.6s 静音后落成 `[对方] …` 句；
- 端点帧产生后，final 事件在约 0–11 ms 内送达理解层（0.6s 端点静音另计）；
- 连续运行期间无 ASR 异常；抓到的句子进入 `QuestionDetector`，非疑问句被正确过滤。

> 注意：环回捕获的是系统混音，测试机上的其他应用声音（视频）也会被识别。正式使用时需要提醒用户关闭与会议无关的音频，或后续加入按进程/设备的路由。

另外，测试中曾出现一次由 ASR 错字触发的误判疑问句；这说明 ASR 准确率会直接影响触发精准率，后续需要结合热词、置信度与更严格的疑问句式来调优。
