# S3 · 端到端延迟验证结论

## 结论（一句话）
**能**。在断句静音等待 ≤ 600ms、流式 ASR 增量出字、云端 LLM SSE 首 token 延迟控制在 500~800ms 内时，端到端首字延迟满足 P50 ≤ 2.0s、P90 ≤ 3.0s 的指标要求。

## 各环节耗时预算表

| 环节 | 预算 (P50) | 预算 (P90) | 说明 |
|---|---|---|---|
| 音频采集与分帧 | 10ms | 20ms | 10ms 环形缓冲 + 格式转换 |
| 断句与静音判定 | 500ms | 600ms | 标点或 600ms 静音判定 |
| 流式 ASR 尾包出字 | 150ms | 300ms | 本地流式 Zipformer |
| 疑问句判定与冷却 | < 1ms | < 2ms | 内存规则匹配 |
| LLM 请求建立与首 token | 600ms | 1200ms | 极简 Prompt + 低延时模型 (DeepSeek/Qwen) |
| UI 动画与卡片渲染 | 50ms | 100ms | WPF 分层窗口透明渲染 |
| **总计端到端首字延迟** | **~1.3s (≤ 2.0s)** | **~2.2s (≤ 3.0s)** | **达标** |

## 优化策略与兜底
- 若网络延迟偏高，断句等待阈值可自适应下调至 400ms
- Prompt 严格限制答案上限 ≤ 40 字，极低 token 消耗，保证首 token 瞬间输出
