# ADR-011: 取消回答 40 字硬限制

## 背景

早期产品定义把“40 字以内”作为核心约束，理由是卡片小、扫一眼就要能说出口。实际使用后出现两个问题：

1. 很多问题需要 2–4 句才能说清（自我介绍、项目经历、方案取舍），40 字导致信息不足；
2. 即使模型想多说，`max_tokens=150` 和浮层 `MaxHeight`（约 3.6 行）也会把回答截断，用户看到的仍然很短。

## 决策

### 1. Prompt 不再出现数字上限

- 删除所有“≤ 40 字”“答案必须极短”的表述；
- 改为软约束：“口语化、可以直接说出口；把必要信息说完整，不要为了简短省略关键信息，也不要长篇大论”；
- 候选人/面试官两种角色的要求都改成“长度按内容需要”。

### 2. 输出 token 只做安全上限

- `LlmOptions.MaxChars` 标记为废弃，默认 0，不再参与 Prompt；
- 新增 `llm.maxTokens`，默认 **1024**，仅作为模型输出 token 的安全上限（防止失控），不是字数限制；
- `OpenAiCompatibleLlmClient` 的 `max_tokens` 改为读取该配置（clamp 64–8192）。

### 3. 浮层允许显示更长回答

- `TxtAnswer.MaxHeight` 从“3.6 行”改为“工作区高度的 65%”；
- 卡片仍保持左下角锚定，长回答时向上生长；
- 超过约 2/3 屏才用省略号截断（屏幕空间限制，不是字数限制）；
- 状态栏文案从“上限 40 字”改为“回答长度不限”。

## 备选方案

- **保留 40 字，只增加“展开”按钮**：浮层点击穿透，交互复杂；且用户明确要求不限制。
- **完全不设 max_tokens**：不同 OpenAI 兼容服务默认值差异大，容易输出失控或报错；保留 1024 的安全上限。
- **浮层内滚动长回答**：卡片点击穿透，滚动不可用；改为限制显示高度 + 省略。

## 后果

- **回答更长**：首 token 延迟基本不变，但完整回答耗时和 token 成本会上升；
- **卡片更大**：长回答会占用更多屏幕；用户可通过字号/位置设置调整；
- **仍需精炼**：Prompt 要求“不要长篇大论”，避免把会议提词器变成论文生成器；
- **旧配置兼容**：旧 `llm.maxChars=40` 仍能反序列化，但不再生效。

## 涉及代码

- `src/Earcue.Core/Models/Prompt.cs`：删除所有数字上限与“极短”表述。
- `src/Earcue.Core/Configuration/EarcueConfig.cs`：`MaxChars` 废弃、新增 `MaxTokens`。
- `src/Earcue.Brain/Llm/OpenAiCompatibleLlmClient.cs`：`max_tokens` 使用配置。
- `src/Earcue.Overlay/OverlayWindow.xaml.cs`：答案最大高度改为工作区 65%。
- `src/Earcue.App/MainWindow.xaml.cs`：状态栏“回答长度不限”。
